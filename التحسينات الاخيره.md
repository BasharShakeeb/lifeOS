# Frontend Architecture & Performance Audit

> **Project:** LifeOS  
> **Objective:** Before implementing any new feature, perform a complete audit of the frontend architecture, responsiveness, and performance to ensure production-quality standards.

---

# 1. Responsive Design (Highest Priority)

Audit every page, component, modal, drawer, form, table, sidebar, navigation, cards, dashboard, and layout.

The application **must be fully responsive** across all screen sizes without horizontal scrolling, broken layouts, overflow issues, or inconsistent spacing.

## Target Screen Sizes

| Device | Width |
|---------|-------|
| Small Mobile | 320px – 480px |
| Large Mobile | 481px – 767px |
| Tablet | 768px – 1023px |
| Laptop | 1024px – 1439px |
| Desktop | 1440px – 1919px |
| Ultra-wide | 1920px+ |

## Verify

- Responsive Grid System
- Flex Layouts
- Responsive Typography
- Icon Scaling
- Sidebar Behavior
- Drawer Behavior
- Navigation
- Forms
- Tables
- Cards
- Dialogs
- Empty States
- Loading States
- Overflow Handling
- Touch Interactions
- Landscape Mode

### Requirements

- No fixed widths unless absolutely necessary.
- Prefer Flexbox and CSS Grid.
- Use responsive Tailwind utilities.
- Avoid layout shifts.
- Ensure RTL support.
- Maintain consistent spacing across all breakpoints.

---

# 2. Frontend Must NOT Handle Business Logic

The frontend should be responsible **only** for presentation.

## Frontend Responsibilities

- Display UI
- Collect user input
- Send API requests
- Display API responses
- Manage temporary UI state
- Handle animations and interactions

## Backend Responsibilities

Move **all business logic** to the backend, including:

- Validation
- Data Processing
- Sorting
- Filtering
- Statistics
- Permission Checks
- Date Calculations
- Priority Calculation
- Business Rules
- Workflow Logic
- Data Transformation
- Aggregation
- Authorization

The backend should return data that is already ready for rendering.

The frontend should never duplicate backend logic.

---

# 3. Fonts Must Be Local

Fonts must never be downloaded from external providers at runtime.

## Requirements

- Store fonts locally inside the project.
- Use `next/font/local`.
- No Google Fonts CDN.
- No external font requests.
- Enable automatic preload.
- Prevent CLS (Cumulative Layout Shift).
- Ensure fonts work offline.

# 4. Performance Audit

Perform a complete performance review.

## Check For

- Unnecessary Re-renders
- Large Client Components
- Missing Memoization
- Heavy Bundles
- Missing Lazy Loading
- Duplicate API Requests
- Hydration Issues
- Oversized Images
- Unused Dependencies
- Slow Initial Load
- Slow Navigation
- Memory Leaks
- Excessive State Updates

## Optimize

- Code Splitting
- Dynamic Imports
- Image Optimization
- Component Memoization
- Request Caching
- Bundle Size
- Rendering Performance

# 6. Code Quality

Verify the entire frontend follows modern engineering practices.

## Requirements

- Clean Architecture
- SOLID Principles
- DRY (Don't Repeat Yourself)
- KISS (Keep It Simple)
- TypeScript Best Practices
- ESLint Compliance
- No Dead Code

# 7. API Integration

Verify all frontend communication with the backend.

## Requirements

- No business logic in API clients.
- Proper error handling.
- Loading states.
- Retry strategy where appropriate.
- Typed API responses.
- Centralized API layer.
- Consistent request handling.

Verify frontend security practices.

# Final Requirement

**Do not implement any new features until this audit is complete.**

The entire frontend must be:

- Fully Responsive
- Lightweight
- Production Ready
- Accessible
- Secure
- Maintainable
- Performance Optimized
- Free of Business Logic

The backend should remain the single source of truth for all application logic.
